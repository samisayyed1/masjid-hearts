# Editing the Masjid Hearts website

Everything on the site can be changed in the browser, without code: articles and their thumbnails, the contact and donation settings, the giving amounts, the home page photo, and every line of text on the English and Arabic home pages.

**Start here:** the site's admin page, `/admin/` (for example https://samisayyed1.github.io/masjid-hearts/admin/). It links to the editor, lists what is still to fill in, and shows every article.

## How it works

The editor is [Pages CMS](https://pagescms.org), a free tool that edits the files in this GitHub repository. Each **Save** is recorded as a change in the repository, the site rebuilds itself, and the change is live in about two minutes. Every earlier version is kept, so any change can be undone.

1. Go to [app.pagescms.org](https://app.pagescms.org) and **sign in with GitHub**.
2. Open **samisayyed1/masjid-hearts** (branch `main`).
3. Pick a section in the sidebar, edit, press **Save**.

To give someone access, the repository owner adds their GitHub account under **Settings → Collaborators** on GitHub.

## The sections in the editor

| Section | What is in it |
| --- | --- |
| **Articles** | Every article: title, summary, date, category, author, **thumbnail / cover photo** and its description, cover pattern (used when there is no photo), *Featured* (large slot on the home page) and *Draft* (hidden from the site). Full guide: [PUBLISHING.md](PUBLISHING.md) |
| **Site settings** | Organisation name, contact email, donation page link, form service URL, social links, the monthly giving amounts and how many hearts each card shows, and the large photo on the home page |
| **Home page text (English)** | Every heading, paragraph, button, list item and form message on the home page, menu and footer |
| **Home page text (Arabic)** | The same for the Arabic home page (`/ar/`) |
| **Media** | Uploaded photos. *Article photos* are for thumbnails and pictures inside articles; *Site photos* are for the home page photo |

### Thumbnails

In an article, use **Thumbnail / cover photo** to upload or pick a photo. It is shown on the article's card on the home page and in the journal, at the top of the article, and as the preview image when the link is shared. Use a landscape photo at least 1600 px wide, and fill in **Describe the cover photo** in one sentence. Without a photo the site draws a pattern cover instead, chosen with **Cover pattern**.

### Giving amounts

The amounts are in **Site settings → Monthly giving amounts**. The title and line of text for each card are in **Home page text → Monthly giving section → Giving level text**, in the same order. If you add a fourth amount, add a fourth entry to the text in both languages too.

### Placeholders in text

A few pieces of text contain words in curly brackets that the site fills in. Keep them as they are:

- `{brand}`: the organisation name
- `{amount}`: the giving amount, e.g. 50
- `{usd}`: in Arabic, the correct word for "dollars" after that amount
- `{email}`: the contact email

## If a change does not appear

Before publishing, the site checks every edit (for example that the email is a real address, links start with `https://`, and no text field was emptied by accident). If something is wrong, **the live site stays as it was** and the change is not published.

To see why, open the repository's **Actions** tab on GitHub: a red cross marks a failed publish. Click it and open **build** to read the message, which names the exact field, for example:

```
Content check found 1 problem(s):
 - Site settings → donateUrl must start with https:// (got "www.example.org")
```

Fix the field in the editor and save again.

## For developers

- Site text and settings: `src/content/site/settings.json`, `home.en.json`, `home.ar.json`
- Articles: `src/content/articles/*.md`; photos in `src/assets/articles/`
- Home page photo: `src/assets/site/`
- Editor layout: `.pages.yml`, generated by `npm run cms` (`scripts/cms-config.py`). Run it after adding a new text key to `home.en.json`
- `npm run validate` runs the content check on its own; `npm run build` runs it first automatically
